## المرحلة 4: صفحة تنفيذ ومتابعة أداء المهمة

عند الضغط على بطاقة المهمة، تُفتح صفحة تفصيلية تجمع كل أدوات التنفيذ والمتابعة.

### 1. رأس الصفحة
- العنوان + النوع + الأولوية + الحالة + شريط تقدم البنود
- عداد تنازلي للاستحقاق (متبقي / متأخر)
- اسم المُكلِّف بجوار اسم المُكلَّف

### 2. صندوق التعليقات والمتابعة
- محادثة بين المُكلِّف والمُكلَّف حول الإجراءات والمشاكل والتعثرات
- Timeline يعرض الكاتب والتاريخ
- يُرى فقط من المُكلِّف والمُكلَّف

### 3. طلبات الإجراءات
- **طلب إعادة جدولة** (تاريخ مقترح + سبب) → معلّق بانتظار موافقة المدير
- **طلب نقل المهمة لموظف آخر** (موظف مقترح + سبب) → معلّق بانتظار موافقة المدير
- لا يتم التغيير الفعلي إلا بعد الموافقة

### 4. إنهاء المهمة
- ملاحظة إنهاء إجبارية + إرفاق صور/ملفات اختياري + نتيجة (نجحت / فشلت)
- بعد الحفظ تُغلق المهمة ويظهر ختم "تم الإنجاز"

### 5. التحديث التلقائي للحالة
- بعد فوات تاريخ الاستحقاق بدون طلب نشط ولا إنجاز → تُحوَّل إلى **متأخرة** تلقائياً + يُنشأ إشعار للمدير والموظف

### 6. تقييم المهام
- بعد إنهاء الموظف للمهمة → إشعار للمدير بـ "مهام بانتظار التقييم"
- شاشة تقييم 1–10 + ملاحظة → يُحفظ في سجل أداء الموظف، ويصل إشعار للموظف بنتيجة التقييم

## المرحلة 5: نظام الإشعارات داخل النظام

### الأحداث التي تولّد إشعاراً
| الحدث | المُستلم |
|---|---|
| تكليفك بمهمة جديدة | المُكلَّف |
| تعديل تاريخ/أولوية/تفاصيل مهمتك | المُكلَّف |
| تعليق جديد على مهمتك | الطرف الآخر |
| طلب إعادة جدولة/توجيه | المدير المُكلِّف |
| الموافقة أو رفض طلبك | الموظف الطالب |
| مهمة أصبحت متأخرة | المُكلَّف + المُكلِّف |
| إنجاز المهمة | المُكلِّف (بانتظار التقييم) |
| تقييم مهمتك | المُكلَّف |

### عرض الإشعارات في الواجهة
- **جرس الإشعارات** في رأس الصفحة (AppShell) — موجود مسبقاً، سنفعّله مع Badge بعدد غير المقروء
- **قائمة منسدلة** (Popover) بآخر 10 إشعارات مع زر "تعليم الكل كمقروء"
- **صفحة `/notifications`** تعرض كل السجل مع فلاتر (الكل / غير مقروء / حسب النوع) وبحث
- كل إشعار قابل للنقر يفتح المهمة المرتبطة مباشرة
- **Realtime** عبر Supabase Realtime ليصل الإشعار فوراً بدون إعادة تحميل

### تفضيلات المستخدم (اختياري ضمن `/account`)
- تفعيل/تعطيل أنواع معينة من الإشعارات (مثلاً: التعليقات، التأخير، التقييم...)

## التفاصيل التقنية

### قاعدة البيانات
- **`task_comments`** (`task_id`, `author_id`, `body`, `created_at`)
- **`task_requests`** (`task_id`, `requested_by`, `kind` enum: `reschedule`/`reassign`, `proposed_date`, `proposed_assignee_id`, `reason`, `status`, `decided_by`, `decided_at`)
- **`task_attachments`** (`task_id`, `file_url`, `file_name`, `uploaded_by`) + Storage bucket `task-attachments`
- توسعة **`tasks`**: `completion_note`, `completion_outcome` (success/failed), `rating` (1-10), `rating_note`, `rated_by`, `rated_at`
- جدول **`notifications`** موجود مسبقاً — سنوسّعه إذا لزم وسنُفعّل Realtime عليه (`ALTER PUBLICATION supabase_realtime ADD TABLE public.notifications`)
- **`notification_preferences`** (`user_id`, `event_type`, `enabled`) — اختياري للمرحلة الأخيرة
- **DB Triggers** على `tasks`, `task_comments`, `task_requests` لإدراج صفوف في `notifications` تلقائياً عند كل حدث

### Cron Job
- مهمة يومية تفحص المهام التي تجاوزت `due_date` بدون إنجاز/طلب نشط → تحوّلها إلى `overdue` وتُدرج إشعارات للأطراف المعنية

### الواجهة (TanStack)
- صفحة جديدة: `src/routes/_authenticated/tasks/$id.tsx`
- مكوّنات جديدة:
  - `TaskCommentsThread`
  - `TaskRequestDialog` (إعادة جدولة / نقل)
  - `TaskCompletionDialog`
  - `TaskEvaluationDialog`
  - `NotificationsBell` (يستبدل زر الجرس الحالي في AppShell) — Popover + Realtime subscription
  - صفحة `/notifications`
  - قسم في `/account` لتفضيلات الإشعارات

## ترتيب التنفيذ
1. قاعدة البيانات: الجداول + Storage bucket + RLS + Triggers على notifications + تفعيل Realtime
2. صفحة تفاصيل المهمة `tasks/$id.tsx` + التعليقات + المرفقات + إنهاء
3. طلبات إعادة الجدولة/النقل + شاشة موافقة المدير
4. شاشة التقييم
5. مكوّن جرس الإشعارات + صفحة `/notifications` + Realtime
6. تفضيلات الإشعارات في `/account`
7. Cron job للمهام المتأخرة
